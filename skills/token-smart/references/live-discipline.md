# 层① 活跃期纪律

默认层。用于任何任务：只压掉无效消耗，不动用户要求的深度、完整交付与领域必需流程。

## 1. 按需读取

从当前请求 + 一小段相关状态摘要开始。先按名称/关键词搜索，再读命中的段落及其必要依赖。仍有效的证据直接复用；出现具体疑问才扩大范围。

摘要是**指向原文的路标**，不是证据，也不授权任何动作。数值、路径、结论以原文为准。

## 2. 单一主责

只调用会改变当前判断的技能。纯查询、格式化、看一眼就能定的修改，不需要一整套方法论栈。分支参考只有在它的触发条件成立时才读。

## 3. 复用现有路径

动手前先弄清真实输入、调用方和输出。优先沿用现有行为、标准库或一段直接的小实现，而不是新依赖和新抽象层。

## 4. 检查具体失败

每次检查前先问：它能发现什么失败？如果它失败了我会改什么？客观事实优先用可执行检查。相关检查通过后就交付；只有出现新改动、新失败、输入过期或仍存实质疑虑时才复检或扩面。用户明确要求的测试照做。

## 5. 把推理花在会改变结果的地方

普通工作用聚焦自审。只有出现重大外部影响、安全或数据丢失风险、未解的关键不确定性，或用户明确要求时，才加一道独立审阅。

**绝不声称**自己改了模型、推理投入、计费或上下文设置——除非宿主确实暴露并确认了该变更。

## 6. 只委派独立工作

可委派的子任务必须有输入、输出和完成条件。给最小的自包含简报，而不是整段历史。评测从代表性样例开始，只有证据能改变判断时才扩展。

## 7. 携带状态，而不是逐字记录

长任务复用宿主已有的任务摘要，或维护**一份**任务范围内的笔记：目标、已验证进展、未解问题、来源指针。不重复已有记忆，琐碎任务不建笔记。周期性运行先判断状态是否变化、工作是否缺失，再进入昂贵处理。

## 8. 压缩说明，不压缩成果

给结论、必要证据和真实阻塞。省掉例行的"我在读文件""我在思考"以及重复总结。用户要求的代码、分析、引用与完整成品一律保留；用户说展开就展开。

## 收尾

请求的交付物和相关检查都完成即停止。缺少关键输入或授权时，只问那个能改变下一步动作的最小问题，同时继续做已授权的独立工作。

用户随时可以说"这次详细展开"加厚说明，或"这次不要按省 token 模式"覆盖本次偏好；两者都优先于本层默认。
